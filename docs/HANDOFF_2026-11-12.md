## 已确认的用户需求与实现范围

- 独立工程为 `/home/raids/Dual_UAV_Interaction`，原单机工程保留不变。
- 两架完整 X4-950，各保留 Airbot Play，臂通过原位置伺服维持初始姿态；没有锁死关节。
- 任务背景为同高度并排的双机协同空中操作。首版仅提供飞行与相互平动干扰，不含共同物体的抓取、接触或约束。
- 一个共享 MuJoCo 世界、一个物理时钟、两个独立 PX4 SITL 进程。每个物理步只推进一次世界。
- 四模式：off、horizontal、vertical、both；面板支持实时切换，模式和 Ah/Az/L 在 Apply 时一起校验。
- 支持两机解锁、起飞、降落、紧急停止、退出，目标间距调节和编队 X/Y 平移，显示两机位置、互扰加速度与合力。

## 互扰模型与坐标

世界 z 向上。令水平中心距为 d，水平 A→B 单位向量为 e：

```text
g = 1 / (1 + (d/L)^2)
a_A = [-Ah*g*e_x, -Ah*g*e_y, -Az*g]
a_B = [+Ah*g*e_x, +Ah*g*e_y, -Az*g]
```

按模式关闭对应分量。水平方向人工设为相互排斥，竖直方向两机都向下；这是用户批准的现象模型，
不是实际尾流方向、力大小或“水平一定比竖直强”的研究结论。

Ah/Az 单位 m/s²、非负有限；L 单位 m、正有限，是半幅水平距离，不是硬截止半径。
默认 mode=off、Ah=Az=0.5、L=2；初始间距 2 m 时，每个启用通道的大小为 0.25 m/s²。
初始起飞增量为 2 m，初始及目标间距最小 1.5 m 仅为场景碰撞外形设置，不是实物安全距离。

源机必须有仿真转子推力；源/接收机还须处于起飞、悬停或降落阶段，且 root 比初始高度高 0.15 m。
地面接收机不加载互扰。关闭模式立即清除旧载荷，没有原风项目的 XY 投影、EMA 或 3 m/s 限制。

将每机加速度按各子 body 质量分配世界系外力 `body_mass * acceleration`，作用在各 body 质心，
确保整机合力为 m*a、关于实时整机质心的互扰合矩为零。PX4 姿态响应、重力和机械臂动力学保留。
不要把力集中加在主机身 root 后仍宣称整机质心合矩为零。

桥接沿用原项目 `(x,-y,-z)` 分量转换，姿态为 w,x,y,z；不额外宣称绝对地理 ENU/NED 对齐。
每机 PX4 本地原点是各自初始 root 位置，编队目标在共同 MuJoCo 世界表达。

## PX4 与运行独立性

使用 `runtime/px4/bin/px4` 这一已编译的 Linux x86-64 SITL 可执行文件，启动两份进程；不是飞控板固件。
本轮没有重新编译或修改 PX4 二进制，也没有复制完整 PX4 源码。
官方基线为 `c2fb48990aacebc938c4e9998c7d5348f858fd22`；二进制沿用原项目的 MuJoCo 浮点真值反馈/X4 适配，
旁路状态估计器，保留 PX4 原生控制回路。因此不能声称已验证真实传感器 EKF2 链路。

新项目正常运行不依赖 `/home/raids/Wind_field_simulation` 中的文件：资源、配置、pymavlink、运行包均独立复制。
运行时命令别名和生成的 etc 链接均在新项目内。二进制内的编译期测试数据路径通过显式 `-t` 本地目录覆盖。
原项目 757 个受保护文件 SHA256 未变；部署时 585 个普通工程文件复制一致。
核对链接时共有 92 个（90 个运行包命令别名，加已创建会话的 2 个 etc 链接），链接数会随新运行增加；
判据应是无损坏或跨项目链接，不是固定总数。

仍共享本机 Python 环境 `env_uav` 和系统动态库。MuJoCo 3.6.0、NumPy 2.4.4、Matplotlib 3.10.9。
当前 PX4 动态依赖还包括 `/opt/ros/jazzy` 下的 libgz-transport13、libgz-msgs10、libgz-utils2 等，
可用 `ldd runtime/px4/bin/px4` 核对；仿真物理仍由 MuJoCo 提供。
来源与授权见 [PROVENANCE](PROVENANCE.md) 和[第三方声明](../THIRD_PARTY_NOTICES.md)，不赋予所有资源统一开源许可。

## 运行命令

在新项目目录使用现有 env_uav；一个命令同时管理两套 PX4，无需另开 PX4 终端。

```bash
cd /home/raids/Dual_UAV_Interaction
/home/raids/miniconda3/envs/env_uav/bin/python scripts/run_simulation.py
```

桌面操作：等两机 connected → Arm both → 确认 armed → Takeoff both → 选择四模式和 Ah/Az/L → Apply settings → Land both → Exit。
如果原单机占用默认端口，可加 `--instance-base 4`。默认实例 0/1、系统 ID 1/2；实例 k 的 TCP 为 4560+k，
Offboard UDP 为 14580+k。状态、参数和日志分别保存在本项目每次运行的 px4/a、px4/b 下。
端口冲突应报错，不结束已有会话；输出目录必须是新目录。

无 PX4 的模型检查：

```bash
cd /home/raids/Dual_UAV_Interaction
/home/raids/miniconda3/envs/env_uav/bin/python scripts/run_simulation.py --check --mode both
```

离线测试：

```bash
cd /home/raids/Dual_UAV_Interaction
PYTEST_DISABLE_PLUGIN_AUTOLOAD=1 MPLBACKEND=Agg \
    /home/raids/miniconda3/envs/env_uav/bin/python -m pytest -q
```

需要实际双 PX4 闭环时：

```bash
cd /home/raids/Dual_UAV_Interaction
/home/raids/miniconda3/envs/env_uav/bin/python scripts/run_simulation.py \
    --headless --auto --mode both --duration 4 --instance-base 4
```

需要窗口就不要加 --headless；自动流程的 --duration 按墙钟时间，日志 50 Hz 按仿真时间。
输出包含 metadata.json、states.jsonl、summary.json、PX4 控制台和 ULog；摘要区分初始模式与最终设置。

## 已修复问题及维护约束

- Takeoff 保留已设置的 XY 编队目标，并拒绝空中重复起飞；不能回退为重置完整 home 目标。
- Land 幂等，重复点击不清除待确认状态。降落目标低于 home 支撑高度 0.2 m，避免近地渐近悬停。
- 只有真实 floor 接触、近 home 高度、低速且稳定 0.7 秒仿真时间才请求解除解锁；请求状态锁存以处理延迟确认。
- 降落中空中意外解除解锁不能直接记为成功。接收确认时仍检查接地状态。
- `-d` 关闭 PX4 stdin EOF 交互 shell 的提示符循环；`-t` 指定本次运行的本地空 test_data 目录。
- TCP 预检使用 SO_REUSEADDR 允许已关闭连接的 TIME_WAIT，但仍拒绝活动监听。
- SIGINT/SIGTERM 设置退出标志，走拥有者清理，避免 Tk 回调吞掉 KeyboardInterrupt。
- 清理只针对本启动器拥有的进程，不使用 pkill/killall 或按进程名批量结束。
- 同时刻双机状态、MAVLink 系统/组件来源过滤、独立参数目录、关模式清旧力、整机质心零互扰合矩均有回归覆盖。
- MuJoCo viewer 使用私有 `_launch_internal` 兼容当前 3.6.0；升级时需要重新核对关闭实现。

历史失败及中断日志保留在 outputs/validation，解释见 VALIDATION.md。不要因早期 summary.success=false 就忽略后续最终成功证据，
也不要删除失败证据后把全部运行描述为成功。
